Website upkeep

Looking after the IIIT Kottayam website

Everything you will normally do — posting a notice, adding a staff member, swapping a PDF, putting up a new banner — is editing a JSON file and saving it. There is no programming involved.

First, the reassuring part

You cannot break the live website from here

The website people visit is a copy. The files on this computer are the original. Changing a file here does nothing to the live site until someone deliberately uploads the new version. Until then you can experiment freely.

The computer checks your work before anything is published. If you make a typing mistake, a check runs automatically and refuses to publish, telling you which file and which line to look at. A mistake means “try again”, not “the website is down”.

Your editor checks it too, as you type. Every list on the site comes with a description of the fields it is allowed to contain, so VS Code completes field names for you, explains what each one does when you hover over it, and underlines a mistake in red the moment you make it — long before you run anything.

The one thing worth pausing over

Deleting files from the public folder. That is where every photo and PDF the website has ever used is stored. Adding is always safe; deleting is the thing to think twice about.

Setting up, once

Two free programs. Install them once and never think about them again.

  1. Node.js — go to nodejs.org and download the version marked LTS. Install it, accepting all the default options.

  2. Visual Studio Code — code.visualstudio.com. Any text editor works, but this one understands the site's files and catches your mistakes as you type. That is worth a lot.

  3. Open the site folder in VS Code: File → Open Folder.

There is nothing to install

The website is built with nothing but Node.js itself — no add-ons, no downloads, no waiting. If you used the older version of this handbook, the npm install step is gone and is no longer needed.

The three commands

These are the only commands you need. Type them in the terminal, in the site folder. In VS Code, Terminal → New Terminal opens one in the right place already.

npm startSee the website on your own computer
npm run checkCheck your files for mistakes
npm run buildPrepare the finished website for uploading

Seeing your changes

Run npm start and wait for it to print a web address — http://localhost:4321. Open that in your browser. This is the website running on your own computer; nobody else can see it.

Leave that terminal open while you work. Every time you save a file the site rebuilds itself in about half a second — refresh the page in the browser to see it. When you are finished, click the terminal and press Ctrl+C to stop.

Checking your work

npm run check reads every content file and tells you about two kinds of problem.

✗ Must fix

A file has a typing mistake, and the website cannot be built until it is corrected. The message names the file, the line and the character, and says what the mistake actually is.

! Worth a look

Something points at a photo or PDF that is not there. The website still works; that one link just will not open. Some of these were already missing on the old website, so they may need to be requested from the office rather than fixed here.

Publishing

npm run build runs the check first and stops if there is anything that must be fixed. When it succeeds it creates a folder called dist — that folder is the website. Hand it to whoever manages the server, or ask them to run deploy.sh.

What a data file looks like

Every file in src/data has the same three parts. 

{
  "$schema": "./_schema/news.json",
  "_help": [
    "Newest item at the top.",
    "new: true shows the animated NEW badge"
  ],
  "items": [
    { "text": "UG Admission 2026 Updates", "link": "/admission26", "new": true },
    { "text": "Convocation notice", "link": "/data/pdf/convo.pdf", "new": false }
  ]
}
PartWhat to do with it
$schemaLeave it alone. It is what makes VS Code help you.
_helpNotes to yourself. Read them; the website ignores them. Add to them freely.
itemsThe actual content. This is what you edit.

A few files hold settings rather than a list — site.json, home.json, footer.json — and those have named sections instead of items. The _help at the top of each one explains its sections.

Four rules that prevent almost every mistake

1. Copy an existing entry, then change it

Never type a new one from scratch. The shape is then always right.

2. Commas between entries, never after the last one

This is the single most common mistake, and the one the check catches most often. 

"items": [
  { "text": "First" },      ← comma, because another entry follows
  { "text": "Second" }      ← NO comma, because this is the last one
]

3. Every piece of text goes in double quotes

"like this". Numbers (170) and the words true and false do not.

4. If the text itself contains a double quote, put a backslash before it

"text": "The \"Gyaan\" laboratory"
All four are caught for you

VS Code underlines every one of these in red as you type, and npm run check catches them before anything is published. You do not have to spot them yourself.

How to do the common jobs

Post a news item

Open src/data/news_full.json for the News page, or src/data/news.json for the box on the homepage. The newest item goes at the top of items. Copy an entry and edit it: 

{
  "text": "Notice regarding the December examination timetable",
  "link": "/data/pdf/exam-timetable-dec.pdf",
  "new": true
}
  • text — the headline people click
  • link — the PDF you uploaded, or a page such as /placement
  • new — true shows the animated NEW badge, false hides it

To remove an item, delete it from its opening { to its closing }, then check the commas between what remains.

Add a photo or a PDF

  1. Put the file in the right folder — see the table above. PDFs go in public/data/pdf/.

  2. Refer to it starting with /data/, and leave out the word public.

    saved at   public/data/pdf/notice.pdf
written as         "/data/pdf/notice.pdf"

Use names without spaces — exam-timetable.pdf, not exam timetable.pdf. Both work, but names without spaces cause far fewer headaches later. Capital letters matter: Notice.pdf and notice.pdf are different files.

Add or update a staff member

Open the right file from the table — faculty_full.json for teaching staff. Copy an existing person and edit: 

{
  "name": "Dr. Example Name",
  "designation": "Assistant Professor",
  "photo": "example.jpg",
  "area": ["Machine Learning", "Computer Vision"],
  "contact": {
    "email": "example at iiitkottayam dot ac.in",
    "phone": "0482-2202100",
    "room": "AC 301"
  }
}

Upload the portrait to public/data/images/ first. Here photo is just the file name, with no folder in front of it.

Keep the email style

Addresses are written as name at iiitkottayam dot ac.in on purpose — it is how the site stops spam robots collecting them.

To remove someone, delete their whole entry, from { to }.

Change the homepage slideshow

Open src/data/slides.json. The top entry appears first.

{
  "image": "/data/images/home/convocation-2027.jpg",
  "caption": "8th Convocation",
  "link": ""
}

Use a wide picture, roughly 1150 × 400 pixels. A tall photo will be cropped top and bottom. Leave "caption": "" for a slide with no text over it, and "link": "" if clicking it should do nothing.

Update a tender

Open src/data/tenders.json. The status number decides which tab it shows under.

statusAppears under
1Live Tenders
2Closed Tenders
3Cancelled Tenders
0Nowhere at all
15 tenders are currently invisible

They carry "status": 0, which shows nowhere. The old website behaved the same way, so this is not new — but if one of those should be visible, change its number to 1, 2 or 3.

Add a new student batch

Open the matching students file. Each batch is a short key followed by the names. Copy the newest block and change the key: 

"b27": [
  "First Student",
  "Second Student"
]

The tab label is worked out from the key, so b27 becomes “2027 Batch” automatically.

Change the scrolling red notice

Open src/data/home.json and find the "marquee" section. To remove the scrolling notice entirely, leave it empty: "marquee": [].

Change the popup that appears on arrival

Open src/data/site.json, find "popup", and change one word to switch it off: 

"popup": {
  "enabled": false
}

Change a menu item

Open src/data/nav.json. Each entry has a label (what people see) and either a link or a list of children for a drop-down. To reorder the menu, move a whole entry up or down inside items.

Change the wording on an ordinary page

Pages such as RTI and Academics are files in src/content/pages/, named after the page — /rti is src/content/pages/rti.html. These contain tags in angle brackets. Change the words, leave the tags alone: 

<li><a href="/data/pdf/PIO-IIITK.pdf">Public Information Officer</a></li>

Here you would change Public Information Officer, which is what people read, or /data/pdf/PIO-IIITK.pdf, which is the file it opens. Leave <li>, <a href= and </a> exactly as they are.

To change the title shown in the browser tab, edit pages.json.

Change the Welcome, Vision or Mission text

Open the matching file in src/content/home/. Each paragraph is wrapped in <p>…</p> and each bullet point in <li>…</li>. Change the words between the tags and leave the tags themselves alone.

The headings above them — “Vision”, “Mission” — are in src/data/home.json, under "headings".

When something goes wrong

Run npm run check. It names the file, the line and the character. These are the messages you are most likely to see.

The message saysWhat it means
Expected ':' after property name A field name is missing the colon after it. It should read "name": "value".
Expected ',' or '}' A comma is missing between two entries.
Expected double-quoted property name Usually a comma left after the last entry in a list. The last one must not have one.
Unterminated string A piece of text was opened with a " and never closed.
Unexpected end of JSON input A bracket or brace was opened and never closed. Look at the end of the file.

A photo does not appear

Check three things:

  • the file really is in public/data/images/
  • the spelling matches exactly, including capital letters
  • there is no stray space inside the quotes

A field name has a red squiggle under it

That field is not one this file supports — usually a spelling slip, titel for title. Hover over it to see what is expected.

The page looks completely wrong

You have probably deleted a tag by accident in one of the .html files. Undo your changes (Ctrl+Z) until it looks right again.

If you are truly stuck

Close the file without saving. Nothing you have done can reach the live website, so abandoning an edit is always safe.
